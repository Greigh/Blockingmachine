### 75. The mobile APK is debug-signed and `versionCode` never bumps — fine for sideloads, wrong for real distribution

- **Where:** `packages/mobile/android/app/build.gradle` (`versionCode 1`, `versionName "1.0.0-rc.9"`), the generated signing config; the `mobile-v1.0.0-rc.9` pre-release.
- **What:** `assembleRelease` signs with the debug keystore — installable and V2-signed, but Android refuses an update install over a differently-signed build, and with `versionCode` pinned at 1 a package manager can never treat a newer build as an upgrade either.
- **Why left:** the distribution channel is undecided (direct sideload vs Play/internal track vs F-Droid); signing belongs to that decision and to secret management, not to the feature branch.
- **Fix shape:** when the channel is chosen — mint a release keystore (out of git), wire `signingConfigs.release` through `gradle.properties`/env so postinstall-generated builds pick it up, and increment `versionCode` per release.
- **Verify:** `apksigner verify --print-certs` on a shipped APK shows the release cert, and a later build installs over it as an update.

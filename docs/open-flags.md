# Open Flags

Flagged but unfixed work, and the decisions behind it, recorded the moment it is
flagged rather than left in conversation. An entry states why it was left, what
it would take, and how a fix could be verified. Closed entries move to the
bottom with the commit that closed them, so the list doubles as a record of
what was deferred and when it was picked up.

Nothing here is scheduled. The list exists so nothing is *relied on* silently.

### 43. The learned model cannot pass its own promotion gate — the 0.9278 vs ≥ 0.99 miss is a feature-coverage limit, and the features it is deferred on do not exist yet

- **Where:** `packages/ai-training/README.md` (v1 results; the M5 verification run); `packages/ai-training/gate.py` `DEFAULT_CONFIG.min_precision_at_recall_90: 0.99`.
- **What:** The v1 metrics report `precision@recall=0.90` of **0.9278** against a design bar of **≥ 0.99**, and the gate fails the model on it — correctly, and the README says so plainly (*"This is the gate working as designed, not a bug: the v1 model does not meet the design bar"*). - **What shipped:** The allowlist-adjusted P@R the fix shape named is now **measured rather than argued**: `precision_at_recall` takes a `keep` mask, the gate drops the test rows the allowlist decides before scoring (mirroring the golden gate's allowlist-first serving semantics), and the result is printed `[info]` and recorded in the report under `metrics.precision_at_recall_90_allowlist_adjusted` alongside the raw number and the decided-row count. - **Fix shape:** Either land the behavioural features the deferral names (daemon/crawler observations feeding the label store — the M4-shaped work the README already describes) and re-measure, or re-examine the bar itself: with the adjusted P@R now in every report, the reviewer has the measured version of "good enough where the allowlist does not already cover it" — but only if they agree the residual miss is acceptable, which is a decision, not a metric.
- **Verify:** `gate.py` over the v1 metrics still FAILs today; it closes when a future model passes the gate as configured, or the config change that passes it records why the adjusted bar is the right one — now with the adjusted number printed next to the raw one instead of having to be argued for.

# HTTPS filtering — P3 implementation plan (Windows + Linux capture adapters)

Sibling to `https-filtering-p1-plan.md`/`p2-plan.md`; implements design-spec §11's P3 line — **Windows + Linux adapters.** Same conventions: task → fresh-eyes review → fix → gate, separate commits, owner's dirty tree untouched, no agent trailers, one logical line per markdown block.

## Locked preconditions (from P0–P2, already true)

- The capture contract is uniform and already exercised: helper accepts the redirected TCP → recovers original destination → writes a PROXY-v2 STREAM header (signature, ver/cmd `0x21`, AF_INET `0x11` / AF_INET6 `0x21`, src = real client, dst = original target) → connects `127.0.0.1:9294` → writes header → splices both directions half-close-aware. `helper/macos/natlook-helper.c` is the reference implementation (~800 lines: fork-per-connection, nonblocking accept, `MAX_CHILDREN` cap, watchdog, state-file re-arm callout).
- Engine runs at `127.0.0.1:9294` (data) / `:9293` (control); `BM_*` env config; the egress loop exemption is a HARD requirement on every platform — the engine's own upstream dials must never be re-captured (macOS solved it with a dedicated `_blockingmachine` user + `user !=` rule).
- `filterProxyManager` already owns `isCaptureServiceInstalled()`/`getCaptureInstallCommand()`/`start()`-squat-gates keyed on those — P3 extends them per-platform (they're darwin-only today: `filterProxyManager.ts:246` returns false off-darwin).
- `caTrustStore.ts` returns `'unsupported'` on win32/linux — P1's explicit deferral: "win32/linux: return 'unsupported' with a named TODO (P3)".
- QUIP suppression posture (block outbound UDP/443 → forced TCP fallback) is the same decision on all platforms.
- Helper build/test posture: macOS ships `helper/macos/{natlook-helper.c,pfvar-fragment.h,build.sh}` + `helper/build-if-darwin.mjs` npm-gated compile; tests are `bash -n`/structural on foreign platforms, live rehearsals operator/docker-gated. Same for P3 — this Mac cannot run win32/linux legs.

## Platform design decisions (pinned here so tasks don't re-litigate)

**Windows — driverless WFP connect-redirect.** `FWPM_LAYER_ALE_CONNECT_REDIRECT_V4/V6` filters referencing the **system-provided callout** `FWPM_CALLOUT_TCP_REDIRECT_CONNECT_LAYER` + a `FwpmRedirectHandleCreate` handle redirect TCP connects to a local listener; the accepted socket's original destination is recovered via `WSAIoctl(SIO_QUERY_WFP_CONNECTION_REDIRECT_RECORDS)` — the exact `DIOCNATLOOK`/`SO_ORIGINAL_DST` analog. **No third-party driver, nothing to vendor/sign** (spec's WinDivert line is superseded: WinDivert means a kernel driver + userspace NAT in both directions; WFP-redirect is kernel-native and lets the helper stay byte-identical in shape to natlook-helper). Filters are **session-scoped** (dynamic `FwpmTransactionBegin`-less adds die with the engine handle) — helper death = fail-open by construction, matching the watchdog philosophy without a flush callout. Egress exemption: exclusion filters (higher-priority sublayer or weight) on `FWPM_CONDITION_ALE_APP_ID` for the engine+helper binary paths, so their dials are never redirected — same posture, mechanism differs (no dedicated user needed on Windows). Requirements: helper runs elevated (WFP needs admin; service runs `LocalSystem`), Windows 10+.
Fallback note: if `SIO_QUERY_WFP_CONNECTION_REDIRECT_RECORDS` proves environment-fragile (it requires the redirect-handle relationship to the accepting process — validate on real Windows CI leg or flag), the escape hatch is the spec's original WinDivert design — do NOT silently substitute it; the plan's tests must distinguish "untested" from "works".

**Linux — REDIRECT + SO_ORIGINAL_DST.** `iptables -t nat -A OUTPUT -p tcp -m multiport --dports 80,443 -j REDIRECT --to-ports <helperPort>` (+ `-m owner --uid-owner blockingmachine -j RETURN` first for egress exemption — dedicated `blockingmachine` system user, mirrors macOS) and `ip6tables` twin. Helper: `getsockopt(fd, SOL_IP, SO_ORIGINAL_DST, &dst)` (v4) / `SOL_IPV6, IP6T_SO_ORIGINAL_DST` (v6). nftables equivalent: `nft add rule ip nat output … redirect` — owner match is `meta skuid`. Support BOTH: installer detects `iptables` (nf_tables backend) vs native `nft` and renders whichever exists; the runtime mechanism is identical either way (REDIRECT → SO_ORIGINAL_DST is a kernel conntrack/NAT feature, table-syntax-agnostic). Persistent rules via a systemd oneshot unit that renders+loads on boot (the anchor-file analog) — helper/service plists become `blockingmachine-helper.service` (root) + `blockingmachine-proxy.service` (`User=blockingmachine`). TPROXY is deliberately NOT chosen (needs route rules + `CAP_NET_ADMIN` on the socket — strictly more moving parts for zero gain here).

## Task 1 — shared helper core + Windows helper + installer

`packages/https-filter/helper/common/` — extract the platform-agnostic body of `natlook-helper.c` into `splice.h`/`splice.c`: PROXY-v2 emit (`emit_proxy_v2(int fd, family, saddr, daddr)`), the bidirectional `poll(2)` splice with half-close, child/watchdog plumbing, bounded-children gate, logging macros. Refactor `natlook-helper.c` onto it (its macOS-only parts — `/dev/pf` open, `DIOCNATLOOK`, state-file re-arm — stay; behavior must be byte-identical, the P1 tests prove it).
`packages/https-filter/helper/windows/redirect-helper.c` (~500 lines; Winsock2 + `fwpuclnt.lib`): `main(helperPort, enginePort)` → `WSAStartup` → `FwpmEngineOpen0` + `FwpmRedirectHandleCreate` → add ALE_CONNECT_REDIRECT_V4/V6 filters (`tcp && (port==80||443)`, system callout key, redirect to `127.0.0.1:<helperPort>`, weight above default; exclusion filter at higher weight `ALE_APP_ID` = engine+helper binaries) → listen `127.0.0.1:<helperPort>` v4+v6 → accept loop → `WSAIoctl(SIO_QUERY_WFP_CONNECTION_REDIRECT_RECORDS, …)` → orig dst → shared PROXY-v2+splice. Windows has no fork → thread-per-connection (`CreateThread`, bounded by the same `MAX_CHILDREN` counter) or `WSAPoll` event loop — pick threads (simpler, mirrors fork semantics); watchdog thread probes `:9294` like the mac one (engine dead → filters are session-scoped so killing the engine handle/failing the process unloads them — document the fail-open-by-construction contract; ALSO explicitly call `FwpmFilterDeleteById`/engine close on clean shutdown).
`packages/https-filter/helper/windows/build.ps1` (or `build-if-win32.mjs` mirroring darwin's): `cl.exe /W4 /WX` or `clang-cl` fallback → `redirect-helper.exe`; npm `build` gate `os.platform()==='win32'` — on this Mac the file is source-only (verify with a parse-level check only — a `-fsyntax-only` via clang in mingw mode if available, else mark build-uncovered honestly).
`scripts/install-windows-capture.ps1` + `uninstall-windows-capture.ps1`: admin-required; registers `BlockingmachineHelper` + `BlockingmachineProxy` services (`New-Service`/sc.exe — helper as LocalSystem, engine as LocalSystem with its own `BM_*` env via registry `Environment` on the service or a `--env-file` the entrypoint reads — pick: service `Environment` multistring under `HKLM\SYSTEM\CurrentControlSet\Services\BlockingmachineProxy`); engine binary resolution mirrors `getCaptureInstallCommand` (the rendered `node filterProxy.cjs` — Windows service wrapping a node exe needs `nssm`-style or `node.exe` as `binPath` with args — pin `binPath = "<node.exe> <bundle>"` sc.exe syntax which supports args; validate service START not just registration — probe `:9293/v1/proxy/status` like the macOS fix).
Tests: `helper-windows.test.ts` skips off-win32; structural tests (script lint `bash -n` n/a — use `powershell -NoProfile -Command` parse check when available, else text-assert: the ps1 contains the service names, the .c contains the ioctl constant) + a `--emit-proxy-v2`-style self-test mode in the C file like the mac `--test` seam (drives splice+v2 on loopback with a fake orig-dst env override — exercises everything but WFP itself, runnable on CI windows-latest).
`scripts/windows-capture-rehearse.ps1` — admin-gated, never auto-run: install → `curl.exe https://example.com` transparent works → blocked-domain 403 → uninstall → verdicts.

## Task 2 — Linux helper + installer + rehearsal

`packages/https-filter/helper/linux/redirect-helper.c` — shared common core; `SO_ORIGINAL_DST` (v4, `SOL_IP`) / `IP6T_SO_ORIGINAL_DST` (v6, `SOL_IPV6` — constant `80` on netfilter; guard both) on the accepted fd; fork-per-connection identical to mac (Linux has fork — reuse verbatim); watchdog probes `:9294`, on sustained death flushes the rules (`system("nft flush ruleset blockingmachine 2>/dev/null; iptables -t nat -D OUTPUT …")` — render the exact counter-rule lines the installer wrote, from a state file like the macOS anchor token posture) → fail-open; re-arm on helper start when state present + rules absent (same reboot posture as `pf-anchor.sh` — a `bm-anchor.sh` Linux twin that renders iptables OR nft rules, stores `/etc/blockingmachine-capture-linux.state` with the mechanism token).
`scripts/install-linux-capture.sh` + `uninstall-linux-capture.sh`: root-required (`[ "$EUID" -ne 0 ]` early die); create `blockingmachine` system user (`useradd -r -s /usr/sbin/nologin`, idempotent); install rules via the detected mechanism: prefer native `nft` (`table ip blockingmachine_nat { chain output { type nat hook output priority -100; meta skuid blockingmachine return; tcp dport {80,443} redirect to :9295 } }` + `table ip6 …`) else `iptables -t nat -A OUTPUT -m owner --uid-owner blockingmachine -j RETURN` + `-p tcp -m multiport --dports 80,443 -j REDIRECT --to-ports 9295` (v6 twin via ip6tables); UDP/443 drop rule (`udp dport 443 drop`, same QUIC suppression — in the SAME table so flush is atomic); persist via `blockingmachine-capture-rules.service` oneshot (ExecStart=`bm-anchor.sh load`) — NOT iptables-save (mechanism-agnostic re-render is the point); `blockingmachine-proxy.service` (`User=blockingmachine`, `Environment=BM_*`, `ExecStart=/usr/bin/node <bundle>`, `Restart=always`), `blockingmachine-helper.service` (root, ExecStart=helper). Port preflight + `/v1/proxy/status` health verify — the two P1-review fixes land on day 1 here. `systemd` hard requirement is honest — detect and die on sysvinit/alpine (msg names them; openrc variant is a flag).
`scripts/linux-capture-rehearse.sh` — DOCKER-gated like `openwrt-live.sh`: `--cap-add NET_ADMIN` container, install inside it, assert `curl https://` transparent + blocked-domain 403 + uninstall cleans rules. Skips without docker — this is the one P3 leg that can actually rehearse on this Mac.
Tests: `captureScripts` suite additions — `--render-only` emits the rules+units to tmp for diff-assert (the p1 pattern); `--preflight-only` seam for the port check; helper C gets the same `BM_HELPER_TEST_DST` env-override self-test as mac/windows.

## Task 3 — platform trust ops (`caTrustStore` win32/linux) + app surface

`packages/core/src/caTrustStore.ts` — fill the `'unsupported'` stubs:
- win32: `trustStatus` = `certutil -user -verifystore Root <thumbprint>` (current-user store — the engine's CA is per-device-per-user anyway; machine store needs admin → user store is the honest default, comment it). `installCa` = `certutil -user -addstore Root <file>` (no admin needed for the user store); `removeCa` = `certutil -user -delstore Root <thumbprint>`. Parse certutil output; a denied/elevated case still surfaces `needs-admin`. Note honestly: user-Root covers apps honoring the Windows store (Chrome/Edge/Firefox-with-enterprise-roots); Firefox's own NSS store is a documented gap (flag — `certutil` on `~/AppData/Roaming/Mozilla/…/cert9.db` needs `nss` tooling we don't ship).
- linux: `trustStatus`/`installCa`/`removeCa` via NSS `certutil` on `~/.pki/nssdb` (`certutil -A -t "CT,C,C" -d sql:$HOME/.pki/nssdb`) when `certutil` exists → covers Chrome/Chromium/Firefox-on-NSS; ELSE system-store detect (`/usr/local/share/ca-certificates` + `update-ca-certificates` needs root → `needs-admin` with the sudo line printed). Missing both → `unsupported` honestly. Same `SecurityRunner` injection seam → generic `PlatformRunner`.
App surface (`filterProxyManager.ts`): `isCaptureServiceInstalled()` — win32: `sc query BlockingmachineProxy` exit/parse (or `HKLM\...\Services\BlockingmachineProxy` registry read — pick the cheaper: `sc query` is already the service idiom); linux: `/etc/systemd/system/blockingmachine-proxy.service` exists (file check mirrors the mac plist check exactly). `getCaptureInstallCommand()` renders the platform's script path (`scripts/install-{windows,linux}-capture.{ps1,sh}` with the same absolute-arg render). `HttpsFilterCard` — the capture hint already gates on `captureServiceInstalled===false`; extend the hint to name the platform's script (the `get-install-script` IPC render now works on all three — verify the darwin-only `platform` gating in the card isn't hiding it on win32/linux).
CLI: `cert` verbs already work via core (win32/linux now live); optionally `blockingmachine capture install` verb printing the per-platform script command (check if a CaptureCommand exists — small).
Tests: runner-fake unit tests for certutil parsing (both platforms); manager platform probes via the existing constructor seam; card hint text per platform (dom test); structural tests for the new scripts.

## Task 4 — consolidated P3 review + flags + docs

Cross-platform review pass (one subagent, all of T1–T3): the PROXY-v2 byte contract must be identical across all three helpers (byte-for-byte — the engine's parser is already tested against the mac emitter; add a shared fixture test: emit from each helper's `--test` mode on its native platform gated, plus a C-level golden-bytes test runnable anywhere by asserting the byte-layout code is common-core); exclusion-filter semantics per platform; service-manager parity (launchd/systemd/sc all KeepAlive-equivalent); the fail-open posture audit per platform (what happens when each component dies — write the matrix into `docs/https-filtering-design.md` §11 or the platform README section).
`docs/open-flags.md`: new entries — WinDivert fallback posture, Firefox-NSS cert gap, openrc/sysvinit unsupported, TPROXY not chosen (why), wfp records-API fragility if untested, QUIC-suppression granularity notes.
`AGENTS.md`: add the P3 helper/build/install notes to the https-filter section (build gating, service names, the `blockingmachine` linux user, WFP callout choice).

## Sequencing

T1 ∥ T2 (disjoint files — common core lands in T1 and T2 consumes it; sequence the common-core extraction FIRST inside T1's prompt OR do the extraction as a tiny standalone commit before dispatching both — safer: dispatch T1 first (it owns `helper/common`), T2 parallel against it since T2's file is new (the common core API is pinned in this plan — T2 codes against `splice.h`'s contract, merge-conflict-free). T3 after both (touches the same manager file but different platform branches — actually disjoint enough to run parallel; it doesn't depend on helper internals). T4 last.
